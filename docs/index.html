面向家庭宽带的自建远程桌面
NAT 穿透适配与多服务器管理

这个分支针对「光猫拨号 + Lucky 反向代理、没有固定公网 IP、端口随拨号变化」的家庭自建场景，对 RustDesk 的信令、打洞与会话链路做了一些网络层适配：能直连时尽量走直连，直连不成立时自动回落中继，远程控制本身不受影响。

说明：P2P 直连能否建立，取决于两端 NAT 类型、运营商网络与防火墙策略，任何打洞方案都无法保证在所有网络下成功。本分支的思路是尽量争取直连，失败时安静地走中继。

Features

这个分支改了什么

围绕「家庭宽带没有固定公网 IP」这一前提，对信令、打洞与会话链路做的具体适配。功能以代码行为为准，效果因网络环境而异。

⚡

ProxyProtocol v1/v2 解码

光猫拨号环境下，Lucky / Nginx 反向代理转发 TCP 时会做 SNAT，服务端看到的客户端地址变成内网 IP，打洞因回环检测而中止。配套的 hbbs 服务端支持解码 ProxyProtocol 头，还原真实公网地址后再参与打洞（需在 Lucky 规则中开启该选项）。

🚀

四通道并发直连探测

IPv4 UDP (KCP)、IPv6 UDP、TCP 打洞与 WebRTC 四类通道同时发起探测，取最先成功的一条。参考 OpenP2P 的端口复用思路做了动态源端口锁定与双向端口回填，处理「同一公网 IP 但端口变化」造成的映射错位。

🔄

中继转直连（需用户确认）

会话先经中继建立，避免开局长时间等待；后台继续探测直连可能性，发现可用路径后弹窗征求同意，确认后重连切换为直连（切换期间画面短暂中断）。每个会话至多提示一次，选择「暂不」后本次会话不再打扰。

🌐

IPv6 双栈兼容与策略一致

修复 Windows 上未 connect 的 UDP 套接字调用 peer_addr 触发 10014/10049 系统错误、导致可用 IPv6 候选被丢弃的问题。服务端强制中继策略（ALWAYS_USE_RELAY / 跨网隔离）同时作用于 IPv4 与 IPv6 两条路径，不留旁路。

🎛️

多服务器 Profile 管理

家庭 Lucky STUN、公司云主机、个人 VPS 与官方节点可以并存为多套配置，支持独立延迟测速与显式切换。所有自建节点都停用时，自动回退官方公共服务器，保证基本连通。

🧭

线路与延迟可见

远程会话的状态栏与信息面板显示当前生效的服务器名称（如「家庭 NAS 节点」）、连接模式（P2P 直连 / hbbr 中继 / WebRTC）以及双向 RTT 延迟，方便判断流量实际走的是哪条路。

🔀

TCP / UDP 独立端口分流

Lucky STUN 会把同一内网端口映射成不同的公网端口。客户端按协议分别取址：UDP 用于注册与心跳，TCP 用于信令协商，避免端口分裂导致的握手超时。填入纯域名时自动补齐默认端口。

📡

DNS TXT 动态寻址

Lucky WebHook 把最新端口映射推送到域名 TXT 记录；客户端内置多源并发 DNS 解析与结果缓存。家庭宽带重拨导致端口变化后，被控端自动热重载，无需手动重启。出于安全考虑，TXT 不下发服务端 Key。

🛡️

端到端加密与自定义画质

沿用 RustDesk 的端到端非对称加密，直连时不消耗服务器带宽。帧率可在设置中自定义（最高 120 FPS，实际取决于设备性能与网络状况），支持 NVENC / AMF / QSV 硬件编解码。

Behavior Diff

与上游 RustDesk 的行为差异

下表描述的是代码行为层面的差异，不构成性能承诺；实际连接效果受两端网络环境影响。

场景 上游 RustDesk 本分支
🌐 反代 / SNAT 环境 服务端看到的是代理的内网地址，触发回环检测后回落中继 hbbs 解码 ProxyProtocol v1/v2，还原真实公网地址参与打洞（需代理侧开启）
🚀 直连探测方式 按固定顺序逐项探测可用链路 IPv4 UDP / IPv6 UDP / TCP / WebRTC 并发发起，取最先成功者
🧬 对称 NAT 端口跳变 判定为对称 NAT 后放弃打洞，走中继 动态源端口锁定与双向端口回填，部分对称 NAT 场景可打通（不保证全部）
🔄 会话中途链路变化 保持初始选路，直至会话断开 中继会话后台继续探测直连，发现后弹窗征求确认再切换，每会话至多提示一次
🎛️ 服务器配置 单组 ID / 中继服务器配置 多 Profile 并存、独立测速、显式切换；全部停用时回退官方公共节点
🧭 链路可见性 状态栏显示加密连接图标 额外显示生效节点名称、直连 / 中继 / WebRTC 模式与 RTT
🪟 Windows IPv6 兼容 未 connect 套接字的 peer_addr 系统错误可能导致候选被丢弃 以 (socket, addr) 元组绕过该系统查询，路由可达才登记候选
📡 动态端口与服务发现 基于静态连续端口规划（21115–21119） TCP / UDP 分别取址 + 纯域名自适应 + DNS TXT 离散端口热重载
Implementation Notes

几处具体问题的处理记录

摘录四个有代表性的问题与对应处理方式，附关键代码片段，便于了解改动边界。

记录 1 · 策略一致性 rendezvous_mediator.rs

强制中继策略在 IPv6 路径上的缺口

问题：服务端通过 ph.nat_type = SYMMETRIC 表达强制中继与跨网隔离策略。此前被控端为规避本地 NAT 探测超时跳过了该检查，且 IPv6 候选不受策略约束，双栈客户端仍可能绕道直连。

处理：恢复信令中的服务端 SYMMETRIC 判定（不引入易超时的本地 Config::get_nat_type()），并把策略检查前置到 start_ipv6 之前：策略要求中继时，不再向对端提供 IPv6 候选。

// 策略要求中继时，不向对端暴露 v6 候选
let policy_relay = ph.nat_type.enum_value() == Ok(NatType::SYMMETRIC) || relay;
if peer_addr_v6.port() > 0 && !policy_relay { start_ipv6(...).await; }
记录 2 · 系统兼容 client.rs / udp_nat_connect

Windows 10014/10049 导致 IPv6 候选被丢弃

问题：Windows 上对未调用 connect() 的 UDP 套接字调用 peer_addr() 会返回 os error 10014 / 10049，可用的 IPv6 候选在竞速开始前就被静默丢弃。

处理：不再依赖运行时系统查询，把套接字与已解码地址以元组 Option<(Arc<UdpSocket>, SocketAddr)> 直接传入打洞逻辑；测试路由可达后才登记候选，避免无 IPv6 路由的主机空耗探测窗口。

// 绕过系统 peer_addr 查询，元组直接供给竞速池
if let Some((udp_socket_v6, v6_target)) = udp_socket_v6 {
  direct_futures.push(udp_nat_connect(udp_socket_v6, v6_target, "IPv6", udp_timeout).boxed());
}
记录 3 · 交互边界 direct_upgrade.rs / ui_session

直连升级提示的计数与防打扰

问题：早期实现在弹窗展示时就消耗重试配额，用户点「暂不」后机会被提前用掉；把计数挪到重连入口，又会被离线重试定时器误消耗；不退出探测则会反复弹窗。

处理：配额定义为单会话提示上限（MAX_UPGRADE_PROMPTS = 1），弹窗后探测任务退出当前会话；常规重连与升级流程相互独立，互不消耗对方的计数。

// 弹窗计数后退出本轮探测，常规重连不受影响
let attempts = handler.upgrade_attempts.fetch_add(1, Ordering::SeqCst) + 1;
handler.ui_handler.msgbox("upgrade-direct", ...);
return; // 本会话不再重复提示
记录 4 · 超时策略 client.rs / punch_udp

打洞超时的局域网 / 广域网区分

问题：原版打洞等待时间偏长，打不通时界面长时间无响应；而无中继配置时超时又被压到 1000ms，慢网环境下本来 1.5–2s 能完成的打洞被提前判负。

处理：局域网保持快速判定；非局域网设置 PUNCH_MIN_MS = 2000 的探测下限并绑定 3s 上限，超时后回落中继，在打通率与回退时延之间取平衡。

// 局域网快速判定，公网给予 2000ms 探测下限
const PUNCH_MIN_MS: u64 = 2000;
let udp_timeout = if is_local { connect_timeout } else { connect_timeout.max(Self::PUNCH_MIN_MS) };

Architecture

网络交互与通信流

从内网服务部署、DNS TXT 分发，到客户端按协议分流的完整链路。示例地址均为文档用保留地址。

1. 内网部署与 Lucky STUN 映射
hbbs (UDP 21116) → STUN 1 (UDP)
映射为公网 host: 198.51.100.123:24869
hbbs (TCP 21116) → STUN 2 (TCP)
映射为公网 tcp: 198.51.100.123:24439
hbbr (TCP 21117) → STUN 3 (TCP)
映射为公网 relay: 198.51.100.123:24867
hbbs (TCP 21115) → STUN 4 (TCP)
映射为公网 online: 198.51.100.123:24115
2. DNS TXT 动态记录
Lucky WebHook 自动同步至域名 TXT 记录：
host=198.51.100.123:24869,

3. 客户端按协议分流
🟢 被控端心跳 / 注册 host (UDP)
🔵 主控握手 / 信令 tcp (TCP)
🟣 穿透失败中继转发 relay (TCP)
📶 对端在线状态探测 online (TCP)
⚡ P2P NAT 打洞通道 端到端直连
Setup Guide

配置教程：四步完成部署

服务端部署 → Lucky 穿透规则 → DNS TXT 记录 → 客户端填写。更完整的说明见仓库内的 LUCKY_STUN_GUIDE.md。

1

部署服务端（Docker Compose 整合镜像 / 原生二进制）

S6 进程托管 · Web 控制台

在内网 NAS、Linux 服务器或软路由上部署。推荐使用本分支维护的 S6 整合镜像 cyzdomo/rustdesk-server-s6:latest，单容器包含 hbbs、hbbr、Web 管理控制台与 ProxyProtocol 解码。

docker-compose.yml 示例
docker-compose.yml 
version: '3.8'

# 若使用 bridge 桥接模式，取消注释以下 networks 及 ports
# networks:
#   rustdesk-net:
#     driver: bridge

services:
  rustdesk:
    image: cyzdomo/rustdesk-server-s6:latest
    container_name: rustdesk-server
    network_mode: "host"  # 推荐 host 模式（直接绑定宿主机网卡）；若改用 bridge 模式请取消注释 ports 映射
    restart: unless-stopped
    # ports:
    #   - "21114:21114"      # HTTP API & Web 控制台后台
    #   - "21115:21115"      # NAT 类型探测 (TCP)
    #   - "21116:21116"      # 信令注册 (TCP)
    #   - "21116:21116/udp"  # 信令注册 & STUN 穿透 (UDP) —— 必须开启
    #   - "21117:21117"      # 中继转发服务 (TCP)
    #   - "21118:21118"      # Web 客户端 WebSocket (可选)
    #   - "21119:21119"      # Web 客户端中继 WebSocket (可选)
    environment:
      # 1. 默认下发中继地址（客户端若匹配到 DNS TXT，会优先自动提取 TXT 内的动态 relay 端口）
      - RELAY=rustdesk.example.com:21117
      - ENCRYPTED_ONLY=1
      # 2. 强制登录：建议初次部署设为 N，待网页端创建用户并测试通过后再改为 Y
      - MUST_LOGIN=N
      - TZ=Asia/Shanghai

      # 3. 内部服务与前端交互绑定（请替换为你的实际域名或 DDNS 域名）
      - RUSTDESK_API_RUSTDESK_ID_SERVER=rustdesk.example.com:21116
      - RUSTDESK_API_RUSTDESK_RELAY_SERVER=rustdesk.example.com:21117
      # 外部访问 Web 控制台与 API 接口的完整 URL（若通过 Lucky 反代或修改了外网端口，请对应修改）
      - RUSTDESK_API_RUSTDESK_API_SERVER=https://rustdesk-api.example.com
      # 容器内公钥文件路径（指向挂载到 /data 的 id_ed25519.pub）
      - RUSTDESK_API_KEY_FILE=/data/id_ed25519.pub
      # 4. JWT 鉴权密钥（可在终端运行 openssl rand -hex 16 生成并替换下方的 xxx）
      - RUSTDESK_API_JWT_KEY=xxx
    volumes:
      # 宿主机数据持久化挂载（请替换为你的实际 NAS/服务器路径）
      - ./data/server:/data     # 存放服务通信密钥及 hbbs 数据
      - ./data/api:/app/data   # 存放 SQLite 数据库及 Web 后台配置
提示：在 Linux / macOS / NAS 终端运行 openssl rand -hex 16 生成随机密钥，替换配置中的 xxx。
2

在 Lucky 中创建 3 条 STUN 穿透规则

登录 Lucky 后台 →「STUN 内网穿透」→ 新建规则：

规则 1：hbbs UDP
协议：UDP
目标端口：21116
规则 2：hbbs TCP
协议：TCP
目标端口：21116
规则 3：hbbr TCP
协议：TCP
目标端口：21117
进阶：开启 Proxy Protocol（光猫拨号 / 免改桥接场景建议开启）

若家庭网络由光猫拨号（NAS 挂在光猫下通过 DMZ 映射），Lucky 转发 TCP 时默认做 SNAT，服务端拿到的对端 IP 是内网地址，打洞会因回环检测失败。在 Lucky 的【STUN 内网穿透】规则 → 编辑 → 高级设置中勾选【附加 Proxy Protocol】（ProxyProtocolV2），本分支的 hbbs 会自动解码协议头、还原客户端真实公网地址，使 TCP 打洞在这类网络下成为可能。

3

配置 Lucky WebHook 或 DNS TXT 记录

将各 STUN 隧道的公网映射结果拼接为 TXT 记录：

host=198.51.100.123:24869,tcp=198.51.100.123:24439,relay=198.51.100.123:24867,online=198.51.100.123:24115,api=https://api.example.com
host：必须。hbbs UDP 注册与 STUN 打洞端口（默认 21116/udp 映射）
tcp：必须（STUN 场景）。hbbs TCP 信令端口（默认 21116/tcp 映射）
relay：必须。hbbr TCP 中继端口（默认 21117/tcp 映射）
online：推荐。hbbs TCP 21115 在线探测端口，用于地址簿快速显示对端在线状态
api：可选。21114 HTTP Web 后台与通讯录同步接口（部署了 rustdesk-api 时填写）
key：已废弃。TXT 不再下发或覆盖 Key，请在客户端「Key」栏手动填写一次 id_ed25519.pub 公钥

在 Lucky WebHook 中可使用 #{RustDesk-UDP.ip}:#{RustDesk-UDP.port} 等变量联动更新 Cloudflare、腾讯云、阿里云 DNS。未配置 online 时，客户端回退到信令心跳探测在线状态；旧记录中的 key= 字段会被忽略。

4

客户端填写与多配置管理

打开 RustDesk 客户端 →「网络设置（ID/中继服务器）」：

模式 A：Lucky STUN 动态穿透
「ID 服务器」只填域名：
rustdesk.example.com
中继 / API 留空，客户端自动从 DNS TXT 提取各端口；「Key」需手动填写一次 id_ed25519.pub 公钥。
模式 B：标准云服务器（阿里云 / 腾讯云等）
直接填公网域名或 IP（可不带端口）：
desk.yourdomain.com
客户端自动补齐 21115 在线 / 21116 信令 / 21117 中继默认端口。
多服务器配置（Multi-Profile）： 在设置页点击「添加配置」，把家庭 STUN 与云服务器保存为不同 Profile，可随时测速并切换生效。

🟢 保存后客户端左下角显示「就绪 (Ready)」，即可发起远程控制。

🎛️ 多 Profile 与线路透传

多套服务器配置并存、延迟测速、显式切换，全部停用时回退官方节点；会话状态栏显示生效节点名称、连接模式与 RTT。

🛠️ 端口自适应与在线流容错

纯域名自建服务器自动补齐默认端口，修复 invalid socket address；HTTP 心跳超时或被拦截时启用 TCP 代理保活降级通道。

FAQ

常见问题

Q1：macOS 下载后提示「已损坏，无法打开」？
这是 macOS Gatekeeper 对未签名应用的默认拦截。在终端执行： sudo xattr -rd com.apple.quarantine /Applications/RustDesk.app 输入开机密码后即可正常打开。
Q2：家庭宽带重拨后公网端口变了，需要手动重启被控端吗？
不需要。被控端周期性轮询 DNS TXT，检测到 Lucky 推送的端口或公网 IP 变化后自动热重载，与新端口重新握手。
Q3：如何确认当前是 P2P 直连还是服务器中继？
看远程窗口顶部标签栏的锁图标：绿色纯锁表示 P2P 端到端直连（悬停显示 Direct and encrypted connection），不消耗服务器流量；带转接箭头的锁表示经 hbbr 中继转发，是打洞失败时的兜底路径。
Q4：默认 30 帧，如何调整到 60 / 120 FPS？
「设置」→「显示」→ 勾选「自定义画质与帧率」，拖动滑块到 60 或 120。可在「硬件加速」中开启 NVENC / AMF / QSV 硬件编解码。实际帧率取决于被控端性能、网络带宽与画面内容，直连下通常更有余量。
Q5：多服务器配置（Multi-Profile）怎么用？
「设置」→「网络（ID/中继服务器）」→「添加配置」，为不同网络环境分别保存节点（如「家庭 NAS - Lucky STUN」「阿里云中继」）。配置列表中可一键启用 / 禁用并查看延迟；所有自建节点都停用时，自动回退官方公共服务器。
Q6：连接后如何查看当前走的是哪条线路？
悬停远程窗口顶部标签栏的安全锁图标，浮窗中除连接模式（加密直连 / 加密中继）外，还显示当前生效的服务器节点名称与地址（如 Server: aliyun (desk.example.com:21116) 或 Server: Official）以及公钥指纹。移动端点击连接状态图标可查看同样信息。
Q7：自建云服务器只填域名、不加端口，能连吗？
可以。对标准云主机，在 ID 服务器直接输入纯域名（如 desk.yourdomain.com），客户端自动为信令分配 21116、中继分配 21117、在线探测分配 21115，避免套接字地址解析错误。
Q8：TXT 记录里的 online 字段有什么用？必须配吗？
online 对应 hbbs 的 TCP 21115 在线探测端口，用于地址簿 / 最近连接列表快速显示远端在线状态（红绿指示灯）。在 Lucky 中为 21115 建一条 STUN 规则并把公网地址填入 online=host:port 即可走专用通道；省略时回退到 21116 信令心跳探测，不影响远程控制、打洞与中继。
Q9：旧版本会从 TXT 自动填 Key，升级后要重新设置吗？
需要手动填一次。DNS TXT 通道未签名、可能被篡改，新版本解析 TXT 时不再写入或覆盖 Key。请在「网络设置」的「Key」栏填写服务端 id_ed25519.pub 公钥，之后无需再改；旧 TXT 中残留的 key= 字段会被忽略。
Q10：光猫拨号没改桥接，为什么也能 TCP 打洞？
光猫路由拨号下，内网 NAS 通过 DMZ / 端口映射对外服务。外部设备连接时，Lucky 等反向代理转发 TCP 默认做 SNAT，服务端看到的客户端 IP 变成 192.168.x.x，触发回环检测导致打洞中止。本分支的 hbbs 支持解码 ProxyProtocol v1/v2：在 Lucky STUN 规则高级设置中勾选【附加 Proxy Protocol】后，协议头携带真实客户端公网 IP 与映射端口，服务端还原后即可正常参与 TCP 打洞。是否成功仍取决于两端 NAT 行为。
Q11：中继如何升级为直连？点「暂不」会被反复弹窗打扰吗？
两端网络初期条件不足时，会话先经中继建立，避免长时间黑屏等待；后台探测任务在不影响操作的前提下继续尝试直连。发现可用直连路径后弹出确认提示：选择升级则重连切换为直连（切换期间画面短暂中断）；选择「暂不」则本会话不再提示。每个会话至多提示一次，常规断线重连不消耗这个额度。服务端策略强制中继的会话不参与升级。
