CORE ADVANTAGES

为什么需要 Lucky 定制增强版？

突破官方单端口同协议假设，为 STUN 动态 NAT 穿透提供全链路深度适配

🔀

TCP / UDP 独立端口分流

Lucky 单协议打洞导致 hbbs 的 UDP（心跳注册）与 TCP（打洞信令）分配为不同公网端口。增强版实现了底层套接字精准分流，从根源解决打洞超时与连接阻塞。

🌐

动态 DNS TXT 自动寻址

Lucky WebHook 自动推送最新端口至 DNS TXT。客户端原生支持 UDP 53 毫秒级多源 DNS 解析，宽带重拨或重启后被控端自动后台热重载，无需人工维护。

⚡

优先局域网直连与公网 STUN / WebRTC P2P 打洞。打洞成功直接点对点传输，零服务器带宽消耗；支持 5~120 FPS 自由调节与 NVENC/AMF/QSV 显卡硬解。

🛡️

端到端 Ed25519 安全加密

完全继承 RustDesk 军工级安全架构。TXT 自动注入服务端公钥 Key，支持非对称握手与端到端 ChaCha20/AES 流加密，杜绝中间人劫持。

TUTORIAL

Lucky STUN 打洞配置保姆级教程

只需 4 步，轻松搭建完全免费的公网自建远程桌面

1

服务端部署 (运行 hbbs 与 hbbr)

在你的内网 NAS / Linux / 软路由上启动服务并生成密钥：

# 启动 hbbs (指定中继并生成 Key)
hbbs -r 0.0.0.0:21117 -k _

# 启动 hbbr (指定 Key)
hbbr -k _

提示：在启动目录下会生成 id_ed25519.pub 文件，复制其内容作为密钥备用。

2

在 Lucky 管理后台创建 3 条 STUN 穿透规则

登录 Lucky 后台 ->「STUN 内网穿透」-> 新建规则：

规则 1：hbbs UDP
协议：UDP
目标端口：21116
规则 2：hbbs TCP
协议：TCP
目标端口：21116
规则 3：hbbr TCP
协议：TCP
目标端口：21117
3

配置 Lucky WebHook 或 DNS TXT 记录

将 3 条 STUN 隧道的公网映射结果拼接为 TXT 记录：

host=198.51.100.123:24869,tcp=198.51.100.123:24439,relay=198.51.100.123:24867,key=你的公钥字符串

💡 在 Lucky WebHook 中可使用变量如 #{RustDesk-UDP.ip}:#{RustDesk-UDP.port} 自动联动更新 Cloudflare、腾讯云、阿里云 DNS。

4

客户端极简填入（一键完成）

打开 RustDesk 客户端 -> 点击「网络设置（ID/中继服务器）」：

ID 服务器 (ID Server)： 你的域名 (如 rustdesk.example.com)
中继服务器 / API / Key：留空即可（客户端自动从 TXT 提取）

🟢 保存后客户端左下角显示「就绪 (Ready)」，即可随时开始高速远程桌面！

FAQ

常见问题与排查指引

Q1: Mac 下载后提示“已损坏，无法打开”？

这是由于 macOS Gatekeeper 门禁对未购买苹果开发者证书的软件进行的默认拦截。只需打开 Mac 终端输入：
sudo xattr -rd com.apple.quarantine /Applications/RustDesk.app
回车输入开机密码后即可直接双击正常打开。

Q2: 家庭宽带重新拨号导致公网端口变化，需要手动重启被控端吗？

完全不需要。RustDesk 被控端内置周期性 DNS TXT 轮询检测机制。当检测到 Lucky 推送的端口或公网 IP 变动时，客户端会自动无感热重载并与新的公网端口握手。

Q3: 如何确认当前远程桌面是 P2P 直连还是服务器中继？

在远程窗口顶部的标签栏（Tab）中：
- 🟢 绿色纯锁图标：表示 P2P 端到端直连（鼠标悬停显示 Direct and encrypted connection），延迟最低且不耗服务器流量；
- 🔄 带转接箭头的锁图标：表示走 hbbr 中继服务器 转发（打洞失败时的兜底保护）。

Q4: 为什么默认是 30 帧，如何开启 60 FPS 或 120 FPS？

进入客户端「设置」->「显示」-> 勾选「自定义画质与帧率」，将滑块拖动到 60 或 120 即可。同时在「硬件加速」中开启 NVENC / AMF / QSV 显卡硬编解码，在 P2P 直连下体验电竞级丝滑控制。
