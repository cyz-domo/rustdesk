ENGINEERING EXCELLENCE

硬核工程演进与问题修复实录

Case 1 · 安全闭环 rendezvous_mediator.rs

服务端强制中继策略与 IPv6 旁路泄漏修复

现场痛点： 服务端通过 ph.nat_type = SYMMETRIC 表达 ALWAYS_USE_RELAY 与跨局域网隔离策略。被控端此前为规避本地 NAT 超时投毒跳过了此检查，导致服务端强制中继被架空；且 IPv6 候选未受策略门禁，使双栈客户端仍能绕道直连。

工业级解法： 恢复信令中的服务端 SYMMETRIC 判定，同时坚决不引入本地易超时的 Config::get_nat_type()；将 policy_relay 检查前置到 start_ipv6 之前，当策略要求中继时彻底关闭 IPv6 候选供给，达成 IPv4/IPv6 双通道 100% 安全闭环。

// 策略中继严禁向对端暴露 v6 候选竞速
let policy_relay = ph.nat_type.enum_value() == Ok(NatType::SYMMETRIC) || relay;
if peer_addr_v6.port() > 0 && !policy_relay { start_ipv6(...).await; }
Case 2 · 系统兼容 client.rs / udp_nat_connect

Windows 10014/10049 错误导致 IPv6 候选误杀修复

现场痛点： Windows 系统上对未调用 connect() 的 UDP 套接字调用 peer_addr() 会抛出操作系统内核级错误 os error 10014 (WSAEFAULT) 或 10049 (WSAEADDRNOTAVAIL)，导致可用 IPv6 候选在并发竞速前被静默丢弃。

工业级解法： 解耦运行时系统查询，将套接字与解码地址以元组 Option<(Arc<UdpSocket>, SocketAddr)> 直接注入打洞引擎；并在底层测试路由成功时才登记候选，既不误杀可用 IPv6，又避免无路由主机浪费 2~3 秒竞速窗口。

// 绕过系统 peer_addr 陷阱，元组直接供给竞速池
if let Some((udp_socket_v6, v6_target)) = udp_socket_v6 {
  direct_futures.push(udp_nat_connect(udp_socket_v6, v6_target, "IPv6", udp_timeout).boxed());
}
Case 3 · 交互体验 direct_upgrade.rs / ui_session

中继转直连升级计数解耦与优雅防打扰重构

现场痛点： 早期升级弹窗展示时立即递增配额并退出循环，用户点击“Not now”后重试机会被提前烧毁；若将计数挪至重连入口，离线自动重试定时器与对端重启也会误吞配额；若不退出又会导致每隔 5 分钟反复弹窗轰炸。

工业级解法： 将配额严格定义为单会话提示上限（MAX_UPGRADE_PROMPTS = 1），弹出后探测任务主动退出当前会话，绝不二次骚扰；常规会话重连与升级流程完全独立，保障升级机会精准生效。

// 弹窗展示精准计数并优雅退出，常规重连不受任何牵连
let attempts = handler.upgrade_attempts.fetch_add(1, Ordering::SeqCst) + 1;
handler.ui_handler.msgbox("upgrade-direct", ...);
return; // 本轮退出，不重复打扰
Case 4 · 性能自适应 client.rs / punch_udp

打破打洞硬等瓶颈，构建 2000ms 深度保底

现场痛点： 原版打洞硬等 3 秒乃至 20 秒，打不通时长时间黑屏卡顿；而在无中继配置时超时时间又被强压至 1000ms，导致慢网环境下原本 1.5s~2s 才能回音的有效打洞被掐断判定为失败。

工业级解法： 区分局域网与公网打洞预算：局域网保持毫秒级极速响应，非局域网设立 PUNCH_MIN_MS = 2000ms 深度探测窗口并绑定 min(3s) 上限，超时毫秒级平滑降级中继，真正兼顾打通率与回退时延。

// 局域网极速响应，公网打洞给予 2000ms 充足往返预算
const PUNCH_MIN_MS: u64 = 2000;
let udp_timeout = if is_local { connect_timeout } else { connect_timeout.max(Self::PUNCH_MIN_MS) };

💡 进阶技巧：开启 Proxy Protocol 启用极速 TCP 打洞（支持光猫拨号 / 免桥接）

若家庭网络由光猫拨号（NAS 挂在光猫下通过 DMZ 映射），Lucky 进行 TCP 穿透时默认会进行 SNAT，导致服务端获取到的对端 IP 变为内网回环而打洞失败。在 Lucky 的【STUN 内网穿透】规则 -> 编辑 -> 高级设置中，勾选【附加 Proxy Protocol】（ProxyProtocolV2）。增强版 hbbs 服务端原生支持该协议头并自动解码还原客户端真实公网 IP，即可在 170ms 内极速建立 TCP 端到端直连！

3

配置 Lucky WebHook 或 DNS TXT 记录

将各 STUN 隧道的公网映射结果拼接为 TXT 记录（包含信令、中继及在线检测通道）：

host=198.51.100.123:24869,tcp=198.51.100.123:24439,relay=198.51.100.123:24867,online=198.51.100.123:24115,api=https://api.example.com
host: 必须。hbbs UDP 注册与 STUN 打洞端口（默认 21116/udp 映射）
tcp: 必须 (STUN)。hbbs TCP 信令控制端口（默认 21116/tcp 映射）
relay: 必须。hbbr TCP 数据中继端口（默认 21117/tcp 映射）
online: 推荐。hbbs TCP 21115 在线探测端口，用于主控端快速查询被控端实时在线状态（红绿灯指示）
api: 可选。21114 HTTP Web 后台与通讯录同步接口（若部署了 rustdesk-api）
key: 已废弃。出于安全考虑 TXT 不再下发或覆盖 Key，请在客户端「Key」栏手动填写一次 id_ed25519.pub 公钥

FAQ

常见问题与排查指引

Q1: Mac 下载后提示“已损坏，无法打开”？

这是由于 macOS Gatekeeper 门禁对未购买苹果开发者证书的软件进行的默认拦截。只需打开 Mac 终端输入：
sudo xattr -rd com.apple.quarantine /Applications/RustDesk.app
回车输入开机密码后即可直接双击正常打开。

Q2: 家庭宽带重新拨号导致公网端口变化，需要手动重启被控端吗？

不需要。RustDesk 被控端内置周期性 DNS TXT 轮询检测机制。当检测到 Lucky 推送的端口或公网 IP 变动时，客户端会自动热重载并与新的公网端口握手，无需手动重启。

Q3: 如何确认当前远程桌面是 P2P 直连还是服务器中继？

在远程窗口顶部的标签栏（Tab）中：
- 🟢 绿色纯锁图标：表示 P2P 端到端直连（鼠标悬停显示 Direct and encrypted connection），延迟最低且不耗服务器流量；
- 🔄 带转接箭头的锁图标：表示走 hbbr 中继服务器 转发（打洞失败时的兜底保护）。

Q4: 为什么默认是 30 帧，如何开启 60 FPS 或 120 FPS？

进入客户端「设置」->「显示」-> 勾选「自定义画质与帧率」，将滑块拖动到 60 或 120 即可。同时在「硬件加速」中开启 NVENC / AMF / QSV 显卡硬编解码，在 P2P 直连下可获得更流畅的控制体验。

Q5: 如何使用多服务器配置 (Multi-Profile) 功能？

进入客户端「设置」->「网络（ID/中继服务器）」，点击「添加配置」按钮，可分别添加不同网络环境的节点（如“家庭 NAS - Lucky STUN”、“阿里云专线中继”）。可在配置列表中一键切换启用或禁用特定节点，并实时查看节点网络延迟。当取消勾选所有自建节点时，客户端会自动切换回退到官方公共服务器保障连通。

Q6: 连接成功后如何查看当前走的是哪条线路？

在远程控制窗口顶部的 Tab 标签栏中，将鼠标悬停在设备名称左侧的安全锁图标上，弹出的浮窗提示中除显示连接模式（🟢 加密直连 / 🟣 加密中继连接）外，还会清晰显示当前会话匹配生效的服务器节点名称与地址（例如 Server: aliyun (desk.chaitin.cloud:21116) 或 Server: Official）以及公钥指纹。在移动端上，点击连接状态图标同样能查看该详情。

Q7: 自建云服务器（如阿里云、腾讯云）只填域名不加端口能直接连接吗？

可以！增强版已实现全链路端口智能自适应。对于标准云主机，在 ID 服务器中直接输入纯域名（如 desk.yourdomain.com），客户端会自动为信令分配 21116、中继分配 21117、在线探测分配 21115，无需手动拼接任何端口号，避免套接字地址错误。

Q8: DNS TXT 记录里的 online 字段有什么用？需要单独配置吗？

online 字段对应 RustDesk 原生 hbbs 的 TCP 21115 在线探测与状态同步端口。在客户端地址簿或近期连接列表中，用于快速轮询并高亮显示远端设备是否在线（红/绿指示灯）。若在 Lucky 中为 21115 创建了 STUN 穿透规则并将其公网地址填入 TXT 的 online=host:port 中，客户端将通过该专用通道刷新状态；如果省略该字段，客户端会自动平滑回退至 21116 信令心跳探测，完全不影响远程控制打洞、中继和音视频流连接。

Q9: 以前的版本会从 TXT 自动填入 Key，升级后需要重新设置吗？

需要。出于安全考虑（DNS TXT 通道未签名，可能被篡改），新版本解析 TXT 时不再写入或覆盖客户端的 Key 配置。请在「网络设置」的「Key」一栏手动填写一次服务端 id_ed25519.pub 公钥即可，之后无需再改动；旧 TXT 记录中残留的 key= 字段会被直接忽略，不影响连接。

Q10: 光猫拨号未改桥接（无公网 IP 直通），为什么现在也能实现 TCP 打洞极速直连？

在光猫路由拨号模式下，内网 NAS 通常通过 DMZ 或端口映射对外提供服务。当外部电脑（如公司内网）连接时，反向代理（如 Lucky）转发 TCP 连接默认会进行 SNAT（源地址转换），导致服务端获取到的客户端 IP 变成内网网段 IP（如 192.168.x.x），直接触发回环检测使得打洞终止。本次增强版在自建 hbbs 服务端原生引入了 ProxyProtocol v1/v2 协议自动解码。只需在 Lucky 的 STUN 规则高级设置中勾选【附加 Proxy Protocol】，ProxyProtocol 头就会自动携带真实的客户端公网 IP 及映射端口，服务端精准还原后即可在 170ms 内极速建立 TCP 端到端打洞，真正做到免公网 IP、免改桥接的高性能直连！

Q11: 中继连接如何自动升级为直连？点了“Not now”会被频繁弹窗打扰吗？

当主被控两端网络初期条件不足或 NAT 映射尚未收敛时，客户端会优先走中继服务器秒连建立会话，杜绝长时间黑屏等待。进入会话后，后台静默守护任务会在不影响操作的前提下持续进行四通道直连竞速探测。一旦检测到可用直连链路，主界面会弹出升级提示。用户点击「Upgrade now」即可在 1 秒内无感热升级到超低延迟 P2P 直连。如果用户暂时不想切换点击了「Not now」，后台探测任务在当前会话周期内会自动静默退出，绝不会每隔几分钟反复弹窗骚扰；同时升级额度会被精准保护，后续网络恢复或手动重连时仍可继续享受升级加速。
